Week 4 Part D step 07 - secrets scan of the repository (tracked files and full git history), 2026-11-07.
Branch week4-partD-07-docs, run with git grep / git log -G in Git Bash.

1. Connection strings with credentials (Server=|Data Source=|Password=|Pwd=|User Id=)
   git grep -n -I -i -E "(Server|Data Source)=[^;\"]+;|Password=|Pwd=|User Id="
   Matches, all without a real credential:
   - .github/workflows/ci.yml: ConnectionStrings__ApexPostTestServer for the throw-away CI SQL Server container;
     the SA password is built from github.run_id/run_attempt per run, never a stored value.
   - README.md, setup-secrets.bat: localhost with Integrated Security / Trusted_Connection (Windows login, no password).
   - sql/perf/Measure-Workloads.ps1: Integrated Security, server and database from parameters.
   - sql/security/create-app-login.sql: usage comment with the placeholder AppPassword="<password>".
   - tests/*: "Server=unused" / "Server=127.0.0.1,1" placeholders and one test-only constant
     (AdminAuditTests.Secret) that proves passwords are redacted from the audit log.
   appsettings*.json: no ConnectionStrings section.

2. JSON Web Tokens (eyJ...eyJ...signature)
   git grep -n -I -E "eyJ[A-Za-z0-9_-]{10,}\.[A-Za-z0-9_-]{10,}\.[A-Za-z0-9_-]{10,}"
   One match: src/ApexPost.Api/ApexPost.Api.http, the deliberately broken token {"sub":"CR-101"} with signature
   "invalid-signature" used for the 401 "not valid" request. @adminToken, @expiredToken and @partnerKey are placeholders.
   git log --all -p -G "<same pattern, 20+ characters per part>": no match in history.

3. API keys, signing keys, secrets with a literal value

   One match: the test constant from point 1. Partner keys and the JWT signing key live only in user-secrets.

6. Passwords in connection strings in history
